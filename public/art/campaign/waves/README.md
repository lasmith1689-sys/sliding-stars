# Incoming wave shuttle art

Original host-native ImageGen source reused from the controller's `docks-sheet-v1` concept, as authorized in the Task 8 brief. No reference-game assets or new paid generation. Prompt, provider/source receipt and explicit alpha body frame evidence are preserved beside `source.png`.

The four frames mean scheduled (closed door), ready (cyan open door), waiting (amber open door), and arriving (accelerating shuttle). This is an arrival preview, not a moving rescue destination or carrier. Crew use the game's existing survivor artwork and independent arrival arcs. Entry cells and queue order come from the engine.

Manifest normalization fixes each stationary nose at x=717 and the landing baseline at y=620 on an 832×832 transparent canvas. The arrival frame includes its full longer trail with a 32px left margin. Delivery uses 256×256 WebP through the existing square pipeline; both display axes use one scale and the manifest center pivot, preserving the approved frame aspect and silhouette. Optimized source/delivery SHA-256, alpha and byte receipts are in `public/optimized/campaign/manifest.json`, generated by the existing preparation script and copied recursively offline. The source is retained for licensing/provenance, not loaded at runtime.

The first Task 8 build used a 768×512 normalization canvas with the square pipeline's default cover resize, cropping the nose/trail. Its prior description of complete padded delivery was incorrect. Review fix round 1 replaces that canvas and removes the renderer's unequal axis scaling; final regenerated deliveries and phone-size checks are recorded in the Task 8 report/playtests.

Game-asset-production discovery found no `game-dev` executable on this host; its external-provider/Blender/package path is unnecessary for this explicitly approved 2D reuse. Visual source review preceded framing. Actual small-phone review is recorded in `validation/campaign/playtests.md`.
